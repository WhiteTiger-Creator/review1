A wind-tunnel ML evaluation desk scores a physics-informed coefficient model before design partners consume batch predictions. Under /app the repository must run a two-stage feature-then-eval pipeline so that /usr/local/bin/wtac-validate feature --campaign-dir DIR --work-dir DIR writes staging features and /usr/local/bin/wtac-validate eval --campaign-dir DIR --work-dir DIR consumes that staging to emit deterministic eval artifacts that satisfy the contracts under /app/docs/, including /app/docs/workflow-overview.md, /app/docs/campaign-schema.md, /app/docs/feature-schema-contract.md, /app/docs/feature-batch-contract.md, /app/docs/eval-staging-contract.md, /app/docs/model-inference-contract.md, /app/docs/eval-metrics-contract.md, /app/docs/dynamic-pressure-contract.md, /app/docs/pressure-coefficient-contract.md, /app/docs/force-integration-contract.md, /app/docs/pitching-moment-contract.md, /app/docs/balance-crosscheck-contract.md, /app/docs/tare-calibration-contract.md, /app/docs/uncertainty-budget-contract.md, /app/docs/artifact-layout.md, /app/docs/fixture-index.md, and /app/docs/api-symbols.md.

Required campaign inputs: conditions.json, geometry.json, pressures.json, balance.json, and tare_runs.json. Required work-directory staging from feature: feature_batch.json and feature_ledger.json. Required work-directory outputs from eval: lift_drag_report.json (batch eval report with model vs label metrics), coefficient_table.csv (feature-path and label-path coefficient rows), calibration_summary.json (tare batch statistics), and uncertainty_budget.json (eval uncertainty metrics).

Preserve every wtac_ API symbol listed in /app/docs/api-symbols.md. Public campaigns live under /app/fixtures/campaigns/. Grading may also use held-out campaigns whose campaign_id values are HELD-ALPHA and HELD-BETA. Grading rebuilds the CLI before verification. All arithmetic is deterministic; do not introduce stochastic solvers or network calls.
