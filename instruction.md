The certificate-transparency monitor under `/app` is a security control against split-view and equivocation attacks by public TLS certificate logs. It gates whether downstream certificate acceptance can trust a newly observed signed tree head, so an accepted dossier must prove that the log's new tree extends the prior trusted checkpoint and that both checkpoints came from the configured log identity.

Bring the supplied Rust project under `/app` to a trustworthy state for this CT security audit; the verifier rebuilds it with Cargo before running it. The final executable must be available at `/app/ctcheck`. The command must read one dossier path, print exactly one JSON verdict to standard output, and update `/app/state/trusted.sth` only when the dossier is accepted in full. The dossier grammar, checkpoint signature transcript, Merkle hashing rules, consistency-proof rules, verdict schema, and state-file durability requirements are defined in `/app/README.md`.

Reject malformed dossiers, unauthenticated checkpoints, non-append-only histories, mismatched log identities, incorrect Merkle roots, and any case that cannot be validated without preserving the previous trusted state byte for byte. The implementation must remain deterministic and offline so the monitor's security decision is reproducible for dossiers with the same public format.
