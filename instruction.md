# Inplace block-mirror hole and content digest skew

Replica-site operators recovered from a mid-transfer network drop during inplace block mirroring. Destination length and mtime matched the source catalog, yet an independent probe still showed elevated generation while sparse hole clusters remained. After two maintenance replay windows the catalog reports finished presentation while probe hole debt and content catchup disagree. Cycle-one convergence rows record synced presentation bytes with flat verified counts. The health probe at `/app/environment/signal/probe.sh` stays green because it only checks catalog state flags.

Fix the blkmir maintenance controller under `/app/environment` so the normal replay pipeline regenerates honest operator artifacts. Rebuild `/app/bin/mirctl` and `/app/bin/viewctl` after edits. Operator notes under `/app/environment/docs/` cover replay variables, fixture fields, hold timing, and lane config. Static JSON under `/app/output` or probe-only edits are insufficient — the verifier clears `/app/output` and reruns the pipeline.

From `/app`, run `bash /app/environment/scripts/repro_mirror.sh`. The driver accepts a workspace root, an output directory, a cycle count (default two windows), a single-cycle index for append-style `mirctl run`, and an append flag that skips duplicate cycle rows on idempotent reruns.

Required exports under `/app/output` are `/app/output/push_trace.json` (segments[].leg_id, segments[].hold_ms, segments[].byte_offset, segments[].epoch), `/app/output/rolling_digest.json` (views[].source, views[].tally, views[].epoch, views[].tally_hex for the latest completed cycle only; catalog-side rows follow the active catalog fixture and probe-side rows follow the active probe fixture; each tally_hex is a lowercase 64-hex digest over twelve little-endian bytes: uint64 tally then uint32 epoch; epoch routing honors `/app/environment/config/epoch_lane.toml`), `/app/output/progress_trace.jsonl` (epoch, op, path; each cycle appends chunk, roll, then latch after prior cycle rows), and `/app/output/convergence_report.json` (cycles[].cycle, cycles[].synced_bytes, cycles[].verified_bytes).

After a two-cycle replay, cycle one should keep verified bytes below synced bytes while hole debt remains or content catchup is incomplete; the closing cycle should settle with them equal and delayed leg sums from `/app/environment/data/seed_payload.bin` converging. Maintenance rank and sealed generation should track only cycles whose verified bytes have caught up to synced bytes. Destination-leg hold timing should stay below the hold floor in `/app/environment/config/push.toml` (hold microseconds divided by 1000) until destination IO completes and both settlement axes close. Leg-b segment rows should keep the probe fixture delayed offset across append resume. Re-running `/app/bin/mirctl run /app/output` for an already-exported settled cycle in append mode must not duplicate trace rows or convergence cycle entries.
