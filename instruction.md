Packaging crew staged /app/parcels with crate manifests, mirror receipts, compression stamps, notice fences, and dependency lane notes for a miniature release kiln. Complete the Vala engraver in /app/engraver. At the packing bench, the entry is make -C /app engrave PARCELS=/app/parcels OUT=/app/out. A consistent parcel set leaves /app/out/crate.index and /app/out/seal.manifest; an inconsistent set leaves no release products.

/app/PARCEL_NOTES.md is the normative release-kiln packing contract. It defines crate assembly, same-family dependency load, mirror affinity on priority ties, compression-family stamp election by notice priority, notice-fence inheritance, root-to-leaf public seal composition, dependency-lane bidding with tightest residual, checksum alphabets, seal wording, release tiers, fixed column widths, product sort keys, and scratch cleanup.

Treat the kiln run as inconsistent when crate ids repeat, a shard references no crate, shard order skips, mirror receipts disagree or lack coverage, compression stamps are unknown, notice fences conflict, dependency-lane bidding finds no feasible candidate, checksum text leaves its alphabet, release tiers jump ahead, seal wording is missing, fields overflow, Vala exits badly, stale products remain, or engraving chips survive. Reordered parcel sheets with identical release facts must keep indexes, manifests, and bytes unchanged.
