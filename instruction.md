`scepd` is a small in-house certificate authority written in Go, under /app/environment. It handles the enrollment side of SCEP: a caller sends a JSON request and, if the authority approves, it signs and returns a certificate. Right now it is far too trusting and hands out certificates for requests it ought to turn away. The authorization weaknesses are in the request-handling code under /app/environment/internal/scep — close them so a caller can no longer obtain a certificate it has not earned. Build with `go build ./...`, and use the `enroll` and `ca-info` subcommands of scepd to see how it behaves. There is no internet access, so don't install anything.

Please keep the service working for every request that should succeed: the well-formed enrollments and renewals under /app/environment/testdata/valid must all still be issued. When you do turn a request away, refuse it through the normal error path instead of crashing, and follow the code's existing habit of leading each error with the component under /app/environment/internal/scep that raised it — so put each check in the component it really belongs to. Two things are easy to get wrong: a request that asks for a longer validity than its provisioner allows should be brought back within the limit and still issued, not rejected; and a provisioner may only certify names inside its own DNS name space (see ca-info), where a `*.` wildcard stands for every host one label beneath it.

When you're done, add a short security_notes.md under /app/environment summarizing what you fixed, naming the CWE classes (CWE-287 and CWE-295) and noting that the design draws on the Apache-licensed step-ca project.
