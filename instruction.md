During an emergency vault-recovery drill, the security team needs an offline cryptographic verifier for quorum bundles that may contain forged, stale, or mathematically inconsistent shares. Implement the verifier in `/app` so it authenticates each custodian submission, tolerates the documented number of Byzantine outliers, enforces role separation, validates refresh commitments and authorized continuity seals, and emits deterministic evidence suitable for incident review. Additional valid bundles following this schema are generated during verification, so the result must come from the supplied security data rather than fixture-specific output.

## Security input and authentication

The input is one JSON object with exactly `case_id`, `prime`, `threshold`, `max_outliers`, `audit_time`, `auth_key_hex`, `required_roles`, `role_limits`, `commitments`, `lineage`, `min_lineage_depth`, and `shares`. `case_id` is non-empty; `prime` is an integer prime from 3 through 65537; `threshold` is an integer from 1 through 8; `max_outliers` is a non-negative integer; `audit_time` is an integer; `auth_key_hex` is a non-empty hex string decoded as the HMAC key; `required_roles` is an array of unique non-empty strings; `role_limits` is an object whose non-empty keys map to non-negative integer caps; and `commitments` maps 1 through 12 unique non-empty epoch names to `sha256:` plus 64 lowercase hex characters. `lineage` has at most `n*(n-1)/2` objects for `n` commitment epochs; each object has exactly `parent`, `child`, `offset`, `continuity_roles`, `continuity_quorum`, and `handoff_seals`. Both names are distinct commitment epochs, each `(parent, child)` pair is unique, multiple parents may target the same child, `0 <= offset < prime`, and the directed epoch graph must be acyclic. `continuity_roles` is an array of unique non-empty strings (it may be empty), `continuity_quorum` is an integer from 1 through 18 and is at least the number of continuity roles, and `handoff_seals` is an array of 1 through 18 unique strings, each `sha256:` plus 64 lowercase hex characters; its input order has no semantic meaning. Roots are epochs with no incoming lineage edge. `min_lineage_depth` is an integer from 1 through the number of commitment epochs. `shares` contains 1 through 18 objects, each with exactly `holder`, `role`, `epoch`, `x`, `y`, `state`, `not_before`, `not_after`, and `mac`. The string fields except `state` are non-empty, every epoch exists in `commitments`, `(epoch, holder)` pairs are unique, `1 <= x < prime`, `0 <= y < prime`, `not_before <= not_after`, and `mac` is 64 lowercase hex characters. JSON types are strict: quoted numbers, booleans, nulls, arrays, or objects must not be coerced into integer fields, including share coordinates, role caps, lineage offsets, continuity quorums, and `min_lineage_depth`.

Authenticate each share with lowercase HMAC-SHA-256 over these UTF-8 lines, in order and with a final newline: `case_id`, `holder`, `role`, `epoch`, `x`, `y`, `not_before`, `not_after`, `state`. Apply `bad_mac`, then `inactive` when state is not exactly `active`, then `outside_window` when `audit_time` is outside the inclusive interval. After that, reject every member of a repeated `(epoch, x)` group as `duplicate_x`; the same x in another epoch is allowed. Rejections are objects with exactly `epoch`, `holder`, and `reason`, sorted by those fields.

## Quorum consensus and refresh lineage

For each epoch with at least `threshold` eligible shares, consider every degree-at-most-`threshold - 1` polynomial obtainable from a threshold-sized subset using arithmetic modulo `prime`. Treat two subsets as the same model when their polynomial values at x=0 through x=`threshold - 1` are identical. A model's support is every eligible share in that epoch lying on the polynomial; the remaining eligible shares in that epoch are outliers. It reaches consensus only when its outlier count is at most `max_outliers`. Inside the support, choose the lexicographically smallest sorted threshold-sized witness that contains every `required_roles` entry and does not exceed any `role_limits` cap; a missing cap means no cap. Reconstruct x=0 as an ordinary non-negative decimal string. The commitment bit is independently true only when `commitments[epoch]` equals `sha256:` plus the lowercase SHA-256 hex of `case_id\nepoch\nsecret_mod\n`.

After all models are known, search refresh lineage over model-and-path states, not just epoch names or one locally preferred state per model. A root model has a depth-1 state only when both its policy and commitment bits are `1`; its path is `[epoch]` and its continuity chain is empty. To extend a particular reachable parent state across an edge, start with holders that occur in both model supports with exactly the same role, then exclude every holder already used by an earlier edge in that state. Enumerate every remaining `continuity_quorum`-sized subset containing every `continuity_roles` entry and sort each holder list. For each list, compute `sha256:` plus the lowercase SHA-256 hex of the UTF-8 lines `case_id`, `parent`, `child`, `offset`, `parent_secret`, `child_secret`, and the comma-joined holders, including the final newline. The edge creates one successor state for every list whose computed seal occurs in `handoff_seals`, provided `child_secret == (parent_secret + offset) mod prime`. Do not select only the first authorized list: a lexicographically later handoff may leave the holders needed for a deeper path. Thus a holder may occur in at most one continuity list along a path. Search every parent edge, every consensus model in its parent epoch, every reachable parent state, and every authorized list. Do not discard a nonpreferred state if its unused-holder set can enable a later edge. States with the same used-holder set may be merged by keeping the deeper one, then the lexicographically smaller epoch path, then the lexicographically smaller continuity chain. A model reports its preferred state by those same priorities. List-of-lists comparison examines edge lists in path order, compares each sorted holder list lexicographically, and treats a proper prefix as smaller. An unreachable or unqualified model has depth 0 and empty path, continuity list, and continuity chain.

## Audit selection and report

Every unique consensus model, including models that fail policy, commitment, or lineage, contributes one audit-frontier record. Hex-encode raw UTF-8 epoch and holder names with lowercase hex, then form `<hex-epoch>|<secret_mod>|<comma-hex-support>|<comma-hex-outliers>|<comma-hex-witness>|<policy-bit>|<commitment-bit>|<lineage-depth>|<comma-hex-continuity-holders>|<comma-hex-lineage-epochs>|<continuity-chain>`. Encode each continuity-chain edge as comma-separated hex holders and join edge segments with semicolons. Holder lists are sorted; the witness is empty and policy bit `0` when no valid witness exists. All lineage fields are empty at depth 0. Sort record bytes lexicographically, append one newline to each, concatenate them, and hash those bytes as `model_frontier_digest`. `evaluated_model_count` is the number of records; with no consensus models the payload is empty and the count is zero.

Only models whose lineage depth is at least `min_lineage_depth` are recoverable. Choose the recoverable model with the greatest lineage depth, then largest support, lexicographically smaller epoch, lexicographically smaller witness-holder list, lexicographically smaller lineage-epoch path, and finally lexicographically smaller continuity chain. A failed commitment, incompatible parent model, missing continuity quorum, or bad transition seal must not stop the search. If nothing is recoverable, use `not_enough_valid_shares` when no epoch has threshold eligible shares, `consensus_not_reached` when no model is within the outlier budget, `role_requirement_unsatisfied` when consensus exists but no model has a valid witness, `commitment_mismatch` when no policy-compliant model also matches its commitment, and `lineage_not_reached` otherwise.

Write exactly one JSON object with `case_id`, `status`, `reason`, `selected_epoch`, `lineage_epochs`, `continuity_holders`, `continuity_chain`, `selected_holders`, `support_holders`, `outlier_holders`, `support_share_count`, `secret_mod`, `valid_share_count`, `evaluated_model_count`, `model_frontier_digest`, `rejected`, and `evidence_digest`. In a recovered report, `continuity_chain` is an array of sorted holder arrays in root-to-terminal edge order, has length `len(lineage_epochs)-1`, and contains no holder twice; `continuity_holders` is its final array or empty for a root. The other holder arrays are sorted, support count equals support length, and `reason` is null. Blocked reports use null epoch and secret, empty lineage and continuity arrays, empty holder arrays, and support count zero. `valid_share_count` is the eligible-share total across all epochs. The evidence digest is `sha256:` plus the lowercase SHA-256 hex of these UTF-8 lines, including the final newline: `case_id`, `status`, reason-or-empty, selected-epoch-or-empty, comma-lineage-epochs, comma-continuity-holders, semicolon-separated comma-holder continuity-chain segments, comma-selected-holders, comma-support-holders, comma-outlier-holders, support-count, secret-or-empty, valid-count, evaluated-model-count, model-frontier-digest, and comma-`epoch/holder:reason` rejections.

## Execution and invalid input

`/app/build.sh` must compile the current Go package into an executable Go ELF at `/app/bin/vaultquorum`. The verifier deletes stale binaries, rebuilds current source, restricts runtime `PATH`, and runs `/app/bin/vaultquorum /absolute/input.json /absolute/output.json`; the binary must perform the evaluation itself. Success writes compact deterministic JSON with one trailing newline and no stdout or stderr. Invalid JSON, wrong fields or exact JSON types, malformed values, duplicate `(epoch, holder)` pairs, unknown epochs, an invalid modulus, or a wrong argument count must exit 2, print exactly `vaultquorum: invalid input` as one stderr line, print no stdout, and leave an existing output file unchanged.
