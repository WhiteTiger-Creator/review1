# Inplace block-mirror hole and content digest skew

Replica-site operators recovered from a mid-transfer network drop during inplace block mirroring. Destination length and mtime matched the source catalog, yet an independent probe still showed elevated generation while sparse hole clusters remained. After two maintenance replay windows the catalog reports finished presentation while probe hole debt and content catchup disagree. Cycle-one convergence rows show synced presentation bytes with flat verified counts. The bundled liveness probe at `/app/environment/signal/probe.sh` stays green because it only checks catalog state flags.

Repair the blkmir maintenance controller under `/app/environment` so the normal replay pipeline regenerates honest operator artifacts. Rebuild `/app/bin/mirctl` and `/app/bin/viewctl` after source changes. Replay variables, fixture field meanings, and workspace layout are in `/app/environment/docs/operator_notes.md`. Export schemas, phased settlement waves, coordinator bind rules, digest authority split, destination-leg gating, append invariants, and delayed-window reconciliation are in `/app/environment/docs/export_contract.md` and `/app/environment/docs/settlement_overview.md`. Writing static JSON under `/app/output` or editing the probe script alone is insufficient — the verifier clears `/app/output` and reruns the pipeline.

From `/app`, run `bash /app/environment/scripts/repro_mirror.sh`. The driver accepts a workspace root, an output directory, a cycle count (default two windows), a single-cycle index for append-style `mirctl run`, and an append flag that skips duplicate cycle rows on idempotent reruns.

The pipeline must emit `/app/output/push_trace.json`, `/app/output/rolling_digest.json`, `/app/output/progress_trace.jsonl`, and `/app/output/convergence_report.json` as described in `export_contract.md`. Each replay cycle runs settlement waves that align with progress trace ops (`chunk`, `roll`, `latch`). Synced presentation bytes may appear before verified accounting catches up. Verified accounting must not credit presentation staging alone, must not advance maintenance rank on staged-only cycles, and must not raise the coordinator seal used for digest authority until hole debt is cleared and content catchup completes on the active probe fixture after all waves apply on a finalized stage pipe.

Digest views must keep catalog and probe authorities split while hole debt or content catchup remains open on a finished catalog presentation. Lane routing for digest epochs loads `/app/environment/config/epoch_lane.toml` at runtime with distinct catalog and probe lanes.

Destination-leg segment rows must keep the probe fixture delayed offset across append resume. Hold timing follows `/app/environment/config/push.toml` and must stay below the configured floor until destination IO completes and both settlement axes close on the probe fixture; partial closure of one axis alone must not advance hold or epoch. While destination IO remains incomplete, destination-leg epoch must not run ahead of source-leg epoch for the same cycle.

Append resume must rebuild destination-leg epoch floors from fixture authorities, lane routing, and prior latch lines in the progress trace — not from partial verified counts in convergence rows. A two-cycle full replay must match cycle-one plus append cycle-two. Idempotent `mirctl run` on an already-settled cycle must not duplicate trace or convergence rows.

After two cycles, cycle one must still show verified below synced when settlement axes were open; the closing cycle settles with verified matching synced and delayed leg sums from `/app/environment/data/seed_payload.bin` converging.
