Acceptance thresholds for raidscrubctl apply.

Output directory default is /app/output. Files written are raid-report.json, scrub-events.jsonl, and array-state.json.

raid-report.json is a JSON object with exactly these keys in any order: arrays_known, uuid_assembly_clean, concurrent_scrubs_peak, unsafe_repairs, spare_activations, resumed_scrubs, duplicate_alerts, recovery_alerts, limits_restored, budget_ok, triage_ok, adjacency_ok, quorum_ok, checkpoint_ok, and accepted. Types are: arrays_known integer count, uuid_assembly_clean boolean, concurrent_scrubs_peak integer count, unsafe_repairs integer count, spare_activations integer count, resumed_scrubs integer count, duplicate_alerts integer count, recovery_alerts integer count, limits_restored boolean, budget_ok boolean, triage_ok boolean, adjacency_ok boolean, quorum_ok boolean, checkpoint_ok boolean, accepted boolean.

Passing requires arrays_known equal to 3, uuid_assembly_clean true, concurrent_scrubs_peak equal to 1, unsafe_repairs equal to 0, spare_activations equal to 1, resumed_scrubs equal to 1, duplicate_alerts equal to 0, recovery_alerts equal to 1, limits_restored true, budget_ok true, triage_ok true, adjacency_ok true, quorum_ok true, checkpoint_ok true, and accepted true. Every one of those fields is independently gated, so a configuration that satisfies thirteen of them still reports accepted false.

Structural gates that keep accepted false even when the counters above look healthy: each known ARRAY must come from mdadm.conf.d rather than only from the monolithic mdadm.conf; each timer must use an unpadded OnCalendar day inside the window published for its array; each scrub helper or service must implement rebuild skipping so a rebuild sync_action publishes scrub_skipped_rebuild; every notification helper under RAID_ROOT/usr/local/lib/raid-scrub must pass a bash syntax check; the bitmap settings must match the inventory; the boot mirror degraded policy must be in force; foreign metadata must stay unassembled; and locks_held must be empty when apply finishes.

scrub-events.jsonl contains one JSON object per line with keys seq, event, array, uuid, and detail. seq is an integer starting at 1 and increasing by one per record. event is one of assemble, foreign_excluded, budget_applied, budget_rejected, triage_selected, spare_activated, spare_withheld, checkpoint_quarantined, checkpoint_rejected, scrub_started, scrub_resumed, scrub_skipped_rebuild, mismatch_observed, repair_authorized, repair_refused, quorum_denied, alert_degraded, alert_recovery, limits_restored, lock_released, and read_error. array is the array name or empty. uuid is the array UUID or empty. detail is a string without raw serial numbers.

array-state.json contains keys generation, arrays, locks_held, speed_limit_min, speed_limit_max, and model_digest. generation is a stable string derived from the configuration, the epoch, the threshold, the campaign, and the urgent array. arrays is a list of objects with name, uuid, level, assembled, degraded_allowed, bitmap, spare_group, sorted by uuid ascending. locks_held must be an empty list after a successful apply. speed_limit_min must be 1000. speed_limit_max must be 200000. model_digest must equal the protected topology digest.

Repeat runs of the same configuration publish byte-identical raid-report.json and array-state.json. No undisclosed pass condition exists beyond the documents in /app.
