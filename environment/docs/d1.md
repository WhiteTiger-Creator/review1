# Mesh record contract

## Commands

All commands run with `ROOT` set to the station root (normally `/app/environment`).

- `bash scripts/s1.sh` — full grid over cases in `docs/d3.txt` × profiles `north` and `south`. Authoritative terminal publish.
- `bash cmd/a2.sh fixtures/f1/book.json scratch/merged/c01_north.tsv` — local pulse only; may report success while durable bind / probes disagree. Not terminal authority.
- `bash scripts/s2.sh` — destructive migration that poisons durable scratch material.
- `bash scripts/s3.sh` — documented recovery path after `s2`. Plain `s1` after `s2` without a complete `s3` is non-terminal.

## Outputs

Primary: `/app/output/reconcile_trace.json`

Companions (per `case_id` + `profile`):

| Kind | Path pattern |
|------|----------------|
| Bind material | `/app/output/kx/<case>_<profile>.bind` |
| Attribution TSV | `/app/output/ty/<case>_<profile>.tsv` |
| Remount JSON | `/app/output/vz/<case>_<profile>.json` |
| Probe JSON | `/app/output/pq/<case>_<profile>.json` |

## Trace schema

```json
{
  "schema_version": 1,
  "blocked": false,
  "grid_seal": "<64 lowercase hex>",
  "runs": [
    {
      "case_id": "c01",
      "profile": "north",
      "bind_hex": "<64 lowercase hex>",
      "attrib_file": "/app/output/ty/c01_north.tsv",
      "remount_file": "/app/output/vz/c01_north.json",
      "probe_file": "/app/output/pq/c01_north.json",
      "pulse_ok": true,
      "terminal_ok": true
    }
  ]
}
```

Required keys: `schema_version` (integer `1`), `blocked` (boolean), `grid_seal` (64 hex), `runs` (array).

Each run object requires: `case_id`, `profile`, `bind_hex`, `attrib_file`, `remount_file`, `probe_file`, `pulse_ok`, `terminal_ok`.

Field meanings:

- `case_id` field identifies the case from `docs/d3.txt`.
- `profile` field is `north` or `south`.
- `bind_hex` field is the 64-hex bind digest for that run.
- `attrib_file` field is the absolute path of the attribution TSV for that run.
- `remount_file` field is the absolute path of the remount JSON for that run.
- `probe_file` field is the absolute path of the probe JSON for that run.
- `pulse_ok` field reports whether local pulse succeeded.
- `terminal_ok` field reports whether probes and remount prefixes match the run bind and every remount entry carries the active generation epoch.
- `blocked` field is true when durable poison markers remain, or when a poison generation journal remains, and `s1` runs without complete recovery.
- `grid_seal` field is the sha256 hex over sorted `case_id|profile|bind_hex` lines.

## Bind digest

For a case/profile pair, let:

- `cur` = integer `cur` from `fixtures/f1/book.json`
- `tag` = string `tag` from `fixtures/f1/book.json`
- `merged_body` = UTF-8 bytes of the merged path→type table for that profile (newline-terminated `path\ttype` rows, sorted by path ascending)
- `map_fp` = sha256 hex of the case's path list from `fixtures/f3/map.json` (paths joined by `\n`, trailing newline)
- `prof` = profile name (`north` or `south`)

Canonical preimage (UTF-8, no trailing newline on the whole string):

```
cur|merged_sha|map_fp|prof|tag
```

where `merged_sha` = sha256 hex of `merged_body`.

`bind_hex` = sha256 hex of that preimage. The bind file body is a single line: `bind_hex` then newline.

Scratch counters, warm flags, prior seal files, and generation journal contents must not enter the preimage. A second clean `s1` after a terminal seal must emit the same `bind_hex` values and the same `grid_seal`.

## Attribution TSV

Header line exactly:

```
path	winner	type
```

Then one row per path present in any drop-in under `fixtures/f2/`, sorted by `path` ascending.

Drop-ins ship as `fixtures/f2/10-core.fc`, `fixtures/f2/15-mid.fc`, `fixtures/f2/20-side.fc`, and `fixtures/f2/30-top.fc`. Drop-in lines use file-context prefixes that may end with `(/.*)?`. The attribution `path` column stores the short key with that optional suffix removed.

Winner selection: among drop-in files that define the path, pick the file whose effective rank is **highest**, where effective rank = base rank from `data/e2.tsv` plus any integer boost from the active profile file under `fixtures/p1/<profile>.toml` inside the `[rank_boost]` table (keys are drop-in filenames). Ties break by filename ascending (lexicographic). Negative boosts are applied as written.

`type` is the type string from the winning drop-in row.

## Remount JSON

```json
{
  "entries": [
    {"slot": "s0", "path": "/var/www", "type": "u:o:t_www:s0", "bind_prefix": "<first 16 hex of bind_hex>", "gen_epoch": "17"}
  ]
}
```

Every slot in `fixtures/f4/slots.json` for the active case must appear. Entries must be ordered by `slot` ascending. `type` must match the attribution winner for that path. `bind_prefix` must equal `bind_hex[0:16]`. `gen_epoch` must be the decimal string of the integer `cur` from `fixtures/f1/book.json` at publish time (not `prev`, not a cached prior generation).

Remount entries must be recomputed from the current bind, attribution, and book generation on every `s1` publish. Per-run warm flags such as `scratch/warm/c01_north.flag` must not short-circuit recomputation when a sidecar cache's entries carry a `gen_epoch` that differs from the active book `cur`, and a successful remount write must clear that run's warm flag when present. Sidecar caches such as `/app/output/vz/c01_north.json.cache` under `/app/output/vz/` are not authoritative across generation bumps.

## Probe JSON

```json
{
  "outcomes": [
    {"path": "/var/www", "ok": true}
  ]
}
```

For each path in the case map: `ok` is true only when **all** of the following hold: (1) remount has an entry for that path, (2) remount `type` equals attribution `type`, (3) remount `bind_prefix` equals `bind_hex[0:16]`, and (4) remount `gen_epoch` equals the decimal string of book `cur`. Any missing entry or mismatch forces `ok` false. Prefix width is exactly 16 hex characters.

## Terminal vs pulse

- `pulse_ok` may be true when local pulse checks pass (merged table present, book readable).
- `terminal_ok` is true only when every probe outcome for the run is `ok`, remount `bind_prefix` values match the run's `bind_hex`, and every remount entry's `gen_epoch` matches the active book `cur`.
- Grid-wide terminal success requires `blocked == false`, every run `terminal_ok == true`, and a complete case×profile grid.

## Generation journal

After a successful non-blocked `s1`, the station writes `scratch/gen_journal.json`:

```json
{"sealed_cur": 17, "sealed_tag": "u17", "grid_seal": "<same as reconcile_trace grid_seal>", "poison": false}
```

`sealed_cur` and `sealed_tag` mirror `fixtures/f1/book.json` at that publish. `grid_seal` must equal the trace `grid_seal`. `poison` is false on a healthy seal.

`scripts/s2.sh` plants a poison journal (among other markers) with `poison` true. While `scratch/gen_journal.json` exists with `poison` true, or while either durable marker exists, `s1` must remain non-terminal (`blocked` true, zeroed seals) until a complete `s3` recovery.

A second clean publish with unchanged book material must keep the same binds and seal, and must rewrite the journal to the same healthy contents (idempotent).

## Grid seal

Sort run rows by `case_id` then `profile`. For each run emit line:

```
case_id|profile|bind_hex
```

Concatenate with newlines (trailing newline). `grid_seal` = sha256 hex of those bytes. Sort key is `case_id` primary, `profile` secondary — not the reverse.

Before assembling the seal, `s1` must clear any residual `scratch/run_*.json` and must not keep a scratch `run_count` counter that changes bind material across publishes.

## Destructive ops / recovery

`bash scripts/s2.sh` writes two durable poison markers under scratch: `durable.bad` and `durable.skew`, plus a poison `gen_journal.json`. While **either** marker exists **or** the journal has `poison` true, `bash scripts/s1.sh` must set `blocked` to `true`, force every `terminal_ok` to `false`, and set `grid_seal` and every `bind_hex` to sixty-four `0` characters.

`bash scripts/s3.sh` must remove **both** markers, remove `scratch/gen_journal.json`, clear `scratch/warm/`, delete `/app/output/**/*.cache`, drop scratch `run_*.json` rows, and remove any `scratch/run_count`. After a complete recovery, `s1` must republish a normal terminal record and rewrite a healthy journal. Idempotent re-publish after a clean terminal seal must keep the same `grid_seal`.
