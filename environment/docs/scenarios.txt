Scenario families exercised by raidscrubctl apply and by the verifier.

Normal operation loads the staged root, validates helper syntax, assembles the three known arrays by UUID, excludes foreign members, applies the per-array throughput ceilings, triages one spare for the declared urgent array, runs offset monthly scrubs with peak concurrency one and adjacency respected, resumes the live parity checkpoint, approves the parity repair through both approvals, restores the global limits, emits a single recovery alert, and publishes outputs.

Budget distribution varies the three ceilings. Any distribution that meets every floor and consumes the whole global maximum is accepted, and two different accepted distributions must both report budget_ok true. A distribution that leaves part of the maximum unassigned, or one that meets the sum while starving an array below its floor, reports budget_ok false and accepted false.

Triage redirection uses --urgent to name a different array. The spare that activates must then come from that array's spare-group, spare_activations stays one, and triage_ok stays true. A spare-groups declaration whose path for one group points inside another group directory makes that group ineligible, so spare_activations drops to zero.

Missing triage removes urgency.conf. No spare may activate, triage_ok is false, and accepted is false.

Calendar shift moves all three scrub days to other days inside their published windows while keeping every pair at least seven days apart. Acceptance must not change. Calendar padding rewrites one day in the zero-padded form, which removes that array's window and raises concurrent_scrubs_peak. Calendar crowding chooses days that sit inside their windows but only one day apart, which keeps concurrent_scrubs_peak at one and drops adjacency_ok to false.

Damaged checkpoint places the upper case corruption marker into the parity checkpoint. The controller refuses to resume it, checkpoint_ok is false, resumed_scrubs drops to zero, and accepted is false until the file is set aside under the .offset.bad name and a fresh decimal offset is written. The flag --corrupt-checkpoint reproduces the damage on demand before the staged root is read.

Quorum families remove the change-board file, or leave a change-board record for a different epoch than the one apply runs under, or remove the UUID from repair.authorize. In each case the parity repair is denied, unsafe_repairs rises, quorum_ok is false, and accepted is false. Running --epoch with a value the change-board file names explicitly is accepted just like the wildcard record.

Threshold raising with --threshold=20 makes the parity mismatch count observation only, so unsafe_repairs stays zero, but quorum_ok is still required, so removing an approval still fails acceptance even though no repair was attempted.

Partial service failure injects a read error during the parity scrub after both approvals. apply must stop further repair for that array, release its lock, keep unsafe_repairs at zero, and still restore limits.

Controlled recovery clears the degraded alert state after a successful recovery alert and must keep accepted true on the next apply.

Repeat application runs apply twice without configuration changes. Report bytes for raid-report.json and array-state.json match exactly across the two publications because the controller emits deterministic key order and array sorting.

Renamed inventory renames member basenames and timer unit file basenames while keeping UUIDs and OnCalendar days identical. Reordered discovery swaps the lexical order of mdadm.conf.d fragments. Relocated staged root points RAID_ROOT at a copied tree. In all three families behaviour must be identical because identity is the UUID.

Unrelated inactive resource adds a disabled foreign array stub and an unused spare group alias. Those resources must not change arrays_known, spare_activations, or accepted.

Monitor mode with --campaign=monitor observes every array and repairs none, and repeating it publishes identical report bytes.

Uppercase UUID tokens in a drop-in must assemble cleanly after normalization.
