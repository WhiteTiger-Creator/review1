# Maintenance policy renderer

`/app/bin/frr-policy-render POLICY_ROOT BASELINE OUTPUT` compiles an integrated FRR maintenance candidate. The program is Bash, accepts exactly three positional arguments, prints the usage line `usage: frr-policy-render POLICY_ROOT BASELINE OUTPUT` and exits 64 for a bad invocation, exits 2 with a `policy:` diagnostic for invalid policy or unsafe paths, and exits nonzero with no partial replacement for I/O errors. A successful invocation is silent, validates its temporary candidate with `vtysh -C -f`, and atomically replaces `OUTPUT` by rename with a new regular non-symlink mode-0640 file. No renderer temporary file may remain. An existing symlink, non-regular file, multiply-linked file, path alias of any input, or symlinked output directory is unsafe: reject it without modifying the output or any link target. A failed invocation preserves an existing regular output byte-for-byte.

The policy root has the same relative layout as `/app/policy`. Its closed set is exactly the fifteen `.conf` files in the table; an extra, missing, non-regular, or symlinked `.conf` file is a policy error. Every input is a line-oriented `key=value` file: blank lines and lines beginning with `#` are ignored, surrounding horizontal whitespace is ignored, and every required key occurs exactly once. Unknown keys, duplicate keys, empty values, and malformed lines are policy errors. The required files and keys are:

| Relative path | Keys |
| --- | --- |
| `maintenance/window.conf` | `change_id`, `router`, `primary`, `standby`, `profile`, `approval` |
| `visibility.conf` | `change_id`, `ipv4_resource`, `ipv6_resource`, `expected_origin`, `min_visibility_percent`, `standby_profile` |
| `advertisements/ipv4.conf`, `advertisements/ipv6.conf` | `family`, `aggregate`, `origin`, `exact_only` |
| `peers/transit-a-v4.conf`, `peers/transit-a-v6.conf`, `peers/transit-b-v4.conf`, `peers/transit-b-v6.conf` | `name`, `role`, `family`, `neighbor`, `remote_as` |
| `preferences/maintenance.conf`, `preferences/normal.conf` | `primary_local_preference`, `standby_local_preference` |
| `prefix-lists/ipv4.conf`, `prefix-lists/ipv6.conf` | `name`, `sequence`, `action`, `prefix`, `range` |
| `route-maps/inbound-primary.conf`, `route-maps/inbound-standby.conf` | `name`, `direction`, `action`, `sequence`, `local_preference` |
| `route-maps/outbound-standby.conf` | `name`, `direction`, `ipv4_prefix_list`, `ipv6_prefix_list`, `default` |

The three CSV files below `POLICY_ROOT/../inventory` are non-symlink regular files with the exact headers shipped in `/app/inventory`; fields are nonempty comma-free tokens. `router.csv` has exactly one row for the maintenance router and that row has role `edge`. `interfaces.csv` has exactly one row for that router for each purpose `router-id`, `<primary>-v4`, `<primary>-v6`, `<standby>-v4`, and `<standby>-v6`, with no duplicate interface, address, or purpose. The router-id row is an IPv4 host prefix equal to the router ID. Each peer address is a plain address of the right family, differs from the local address, and belongs to its purpose's interface prefix; IPv4 peers cannot be network or broadcast addresses. `contacts.csv` contains each role `change-owner`, `rollback-owner`, and `observer` exactly once, with distinct team/channel pairs.

The baseline is a non-symlink, singly-linked regular file. In addition to exactly one `frr version`, `frr defaults`, and `service integrated-vtysh-config` line, it has exactly one hostname, BGP ASN, and BGP router ID matching inventory; exactly the two policy aggregates as its only `network` statements; and exactly the four policy neighbor/remote-AS pairs. This reconciles the proposed policy against the real starting state rather than an unrelated template.

The renderer cross-checks all fragments before writing. Change IDs and standby profiles agree; approval is `approved`; peer names match the primary/standby roles, families are correct, and each role's two peers share one remote AS. Primary and standby names, remote ASNs, and same-family neighbor addresses are distinct, and neither remote ASN equals the local ASN. Normal preference favors primary over standby, maintenance preference favors standby over primary, and all preferences are in range. Both advertisements use the inventory ASN and exactly match the visibility resources; `exact_only=true`; prefix-list actions are `permit`, ranges are `exact`, and their prefixes match the advertisements; inbound maps are `in permit`, and each local preference matches its corresponding primary or standby maintenance preference. Route-map sequences are independent ordering values. The outbound map is `out`, names both prefix lists, and has `default=deny`. Policy names and the router hostname use only letters, digits, `_`, and `-`, beginning with an alphanumeric character. Numeric ASNs, preferences, and sequences are canonical decimal integers in 1..4294967295, visibility is 1..100, aggregates are canonical network CIDRs of the declared family, peer addresses have no prefix, and the router ID is IPv4.

On success the integrated output deterministically contains the baseline global lines and policy hostname; the two exact prefix lists; primary and standby inbound maps; an outbound standby map with IPv4 permit sequence 10, IPv6 permit sequence 20, and deny sequence 100; one BGP process using the inventory ASN/router ID; all four neighbor remote-AS statements; exactly one matching `network` per address family; both IPv6 activations; inbound maps on the matching peers; and the outbound map only on the two standby peers. It contains no other `network`, outbound neighbor map, `ge`, or `le` clause.
