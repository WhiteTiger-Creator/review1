# Routing evidence change policy

Change `CHG-RIS-EDGE-042` uses the current RIPEstat Routing Status v3.4 endpoint:

`https://stat.ripe.net/data/routing-status/data.json?resource=<percent-encoded-resource>`

The exact queries are `193.0.0.0/21` and `2001:67c:2e8::/48`. Perform rounds `01`, `02`, and `03` completely in that order, fetching IPv4 before IPv6 within each round. Generate one fresh lowercase RFC 4122 version-4 UUID for the entire acquisition. Preserve each final HTTP response header block and body using the filenames in `evidence_format.md`; redirects may be followed only when intermediate header blocks are discarded, so each retained header file contains exactly one final `HTTP/` status block. A retained header block includes the terminating blank line and therefore ends with `\r\n\r\n` or `\n\n`. Send a descriptive User-Agent containing the router and change ID. The response body is evidence and must not be reformatted. Acquisition must fail on HTTP errors, incomplete transfers, missing `Date`, a non-JSON content type, a non-HTTPS final URL, failed TLS verification, or inconsistent transfer measurements.

The gate policy is `/app/policy/visibility.conf`. An aggregate is safe only when the response has status `ok`, its resource is an exact string match, its origins array contains exactly AS3333, its `more_specifics` array is empty, and its matching address-family visibility is at least 95 percent. At acquisition, each final HTTP `Date` must be within 45 minutes of the current UTC time. The current RIS `query_time` is aligned to an eight-hour collection point and may therefore trail that header; it must be no more than 12 hours older than the final HTTP `Date` and never later than it. Verification may occur later and therefore checks this retained relationship rather than comparing the header to verifier wall-clock time again.

Within each round, IPv6's final HTTP `Date` must not precede IPv4's. For each family, a later round must not precede the prior round, and the span from round `01` IPv4 to round `03` IPv6 must not exceed 20 minutes. Equal second-resolution dates are allowed. Client `started_at` and `completed_at` values use canonical UTC RFC 3339 with six fractional digits and `Z`; each start is no earlier than the prior completion, each completion is no earlier than its start, and every HTTP `Date` lies between five minutes before its start and five minutes after its completion. These constraints prove acquisition order without relying on file modification times. The six captures are recorded in sequence order in the chained acquisition ledger defined in `evidence_format.md`.

Run `/app/bin/ris-evidence-gate` once for each round. Its three byte-exact outputs are authoritative round decisions. Each invocation must exit zero without standard output or standard error and is authenticated in the ordered gate-execution chain. The consensus is `APPLY_STANDBY` with profile `transit-b-maintenance` only if all three rounds say `APPLY_STANDBY` with that profile. If any well-formed round says `HOLD` with a null profile, consensus is `HOLD` with a null profile. Any unknown decision, wrong profile, inconsistent change ID, malformed round output, missing round, or invalid gate audit aborts rather than becoming a hold. The consensus authenticates both final ledger byte streams.

Build an apply candidate twice, into independent temporary files, with `/app/bin/frr-policy-render`; both successful outputs must be byte-identical before one becomes the retained candidate. A hold candidate is an exact copy of `/app/etc/frr/running.conf`. The rendering provenance defined in `evidence_format.md` authenticates the installed renderer, protected source manifest, baseline, and selected candidate, and reports whether the double render reproduced. Renderer failure, a reproduction mismatch, or FRR validation failure must not leave a completed bundle.

Validate the staged file using `vtysh -C -f /app/change/frr.conf`. Its combined standard output and standard error, even when empty, is retained as the validation log. A nonzero validation result is never acceptable.
