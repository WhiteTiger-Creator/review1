The risk lattice has ordered severity levels and ordered recency levels from `/app/data/lattice_config.json`. Probability must be nondecreasing as severity increases and nondecreasing as recency increases. Every configured severity/recency pair must appear in the fitted surface, even if there is no observation row for that cell.

For each smoothing candidate `alpha`, start each cell with all observation rows for that cell pooled as `events` and `trials`. Reject the run without changing existing outputs if an observation has an unknown level, negative counts, `events > trials`, if validation/scoring cases name unknown levels, or if a candidate shrinkage value is outside `[0, 1]`. The starting probability for a cell is `(events + alpha) / (trials + 2 * alpha)`; if both the denominator and `alpha` are zero, use `0.5`.

Apply deterministic monotone pooling to the candidate surface. Each cell begins in its own block with its own event/trial totals. During one sweep, visit cells by severity order and then recency order. For each visited cell, first compare it with the next severity cell at the same recency, then compare it with the next recency cell at the same severity. If the left/lower block probability is greater than the right/upper block probability, merge the two whole blocks and assign every cell in the merged block the pooled probability `(sum_events + alpha * block_cell_count) / (sum_trials + 2 * alpha * block_cell_count)`. Repeat full sweeps until no merge occurs.

For every configured `candidate_shrinkage` value, transform the monotone-pooled probabilities toward the global training base rate. The global base rate for an alpha is `(total_events + alpha) / (total_trials + 2 * alpha)`, or `0.5` when the denominator is zero. Clip probabilities only for logit safety to `[1e-15, 1 - 1e-15]`, then compute `shrunk = sigmoid((1 - shrinkage) * logit(cell_probability) + shrinkage * logit(global_base_rate))`. This shrunk surface is still monotone.

For each alpha/shrinkage pair, fit a one-dimensional isotonic recalibrator from that pair's validation predictions. Sort validation cases by raw shrunk probability and then `case_id`. Each validation case starts as a block with `weight`, `weighted_events = weight * label`, `min_raw_probability`, and `max_raw_probability`; if a block's calibrated rate is greater than the following block's rate, merge the two adjacent blocks and repeat until block rates are nondecreasing. A block's calibrated rate is `weighted_events / weight`. To calibrate any raw cell or scoring probability, use the calibrated rate of the first block whose `max_raw_probability` is greater than or equal to the raw probability; use the first block below the first range and the last block above the last range.

Evaluate each candidate pair on `/app/data/validation_cases.json` twice: `raw_validation_nll` uses the uncalibrated shrunk probabilities, and `calibrated_validation_nll` uses the isotonic recalibrated probabilities. Both use probabilities clipped only for log safety to `[1e-15, 1 - 1e-15]`, and each case contributes `weight * -(label * ln(p) + (1 - label) * ln(1 - p))`. Select the alpha/shrinkage pair with the lowest unrounded calibrated validation NLL, breaking ties by smaller alpha and then smaller shrinkage. The final JSON `validation_nll` is the selected calibrated NLL. JSON probabilities and NLL values are rounded to six decimals. Candidate scores are sorted by alpha and then shrinkage, cells are sorted by severity then recency, selected calibration blocks are sorted by raw probability range, and scoring cases are sorted by `case_id`. Decisions use `/app/data/lattice_config.json` thresholds: probability at least `alert` is `alert`, otherwise probability at least `monitor` is `monitor`, otherwise `clear`.

`/app/out/current_model.tsv` has exactly the header `severity	recency	probability	decision` followed by one row per fitted cell in severity then recency order. The decision in each TSV row is computed from that cell's rounded probability using the same thresholds. The JSON `input_sha256` is the SHA-256 digest of the raw bytes of `lattice_config.json`, `observations.json`, `validation_cases.json`, and `scoring_cases.json` joined in that filename order.
