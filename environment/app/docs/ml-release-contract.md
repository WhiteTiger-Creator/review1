# Orbital PSF model release contract

The published SQLite campaign is the source of truth, including every release threshold. A campaign is valid only when sample indices are contiguous from zero, sample identifiers are unique, there are at least two distinct sites, every site has both labels, exactly nine ordered feature references exist, and at least three model heads have contiguous orders and one finite weight per feature. All paths are absolute. The complete catalogue, cohort, feature-reference, head-order, and weight validation finishes before constructing or sending the first HTTP request; a single-site catalogue is invalid even if that site contains both labels. Runtime registry threshold changes must control gate outcomes without changing model calculations or using bundled expected answers.

Each response tile is cropped to its square ROI, then an 8-bit sample `p` becomes `(p - intensity_offset) * intensity_gain`. Feature 0 is the calibrated ROI mean divided by 255 and feature 1 is the population standard deviation divided by 255. Subtract the calibrated mean and multiply by the separable symmetric Hann window `0.5*(1-cos(2*pi*i/(N-1)))`. Run a two-dimensional FFTW real-to-complex transform and divide stored magnitude-squared values by the square of the two-dimensional window sum.

For stored column `x`, Hermitian multiplicity is one at `x=0` and also at `x=N/2` only when `N` is even; every other stored column has multiplicity two. For each row use integer `ky=y` when `y <= N/2` and `ky=y-N` otherwise, for both odd and even `N`. Assign the coefficient to integer bin `floor(hypot(x,ky))`; bin 0 is ignored and report bins 1 through 6 use zero-based output positions 0 through 5. Features 2 through 7 are `log1p` of those multiplicity-weighted mean powers. Feature 8 is `log1p((bin4+bin5+bin6)/max(bin1+bin2+bin3,1e-30))`. Empty bins or non-finite values are failures.

For a head, compute `sigmoid((intercept + sum(weight_i*feature_i))/temperature)`. The ensemble probability is the vote-weighted mean of head probabilities. Uncertainty is the largest head probability minus the smallest. Abstain only when uncertainty is strictly greater than `abstain_spread`; the stored prediction still uses `probability >= decision_threshold`.

Coverage and balanced accuracy use non-abstained samples. Brier score and equal-width expected calibration error use every sample. ECE includes probability 1 in the final bin. Each site cohort reports count, coverage, TPR, and FPR from non-abstained samples; the FPR gap is the maximum site FPR minus the minimum. Feature drift is `abs(observed_mean-reference_mean)/reference_scale`, and the maximum is gated.

The balanced-accuracy interval uses the configured number of deterministic stratified bootstrap replicates. Strata are sorted by `(site_id,label)`. Within each stratum, each draw selects `uint64_be(sha256("campaign|revision|replicate|site|label|draw")[:8]) mod stratum_size`. Sort replicate scores. The lower index is `floor(0.025*R)` and the upper index is `ceil(0.975*R)-1`.

A release is `accepted` only when all six current database gates pass: coverage, lower balanced-accuracy bound, Brier, ECE, FPR gap, and maximum feature drift. Otherwise it is a valid `rejected` release.

The native radial helper must pass odd- and even-dimension conformance with every caller-owned input and output buffer bounded by inaccessible guard pages. The conformance run places each exact buffer at both the leading and trailing guard boundary, makes the input power buffer read-only during the call, verifies the complete radial sums and counts, and treats any underrun, overrun, or input write as fatal. Compile the helper with `-fsanitize=undefined -fno-sanitize-recover=undefined -fno-omit-frame-pointer`, `_FORTIFY_SOURCE=3`, and strong stack protection; run with `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`. Protected guard pages are the required address-boundary mechanism for this conformance check.

`/app/bin/fft-check` is the public smoke-test binary. Its output must include an `assigned=` summary for both `47x47` and `48x48`; it may report each dimension once or repeat it for separate leading/trailing guard placements. The protected-boundary conformance requirement concerns the exercised memory positions, not an exact number of output lines.
