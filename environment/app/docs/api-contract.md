# Sample and release HTTP contract

`orbit-api` accepts `--db ABSOLUTE_PATH` and the optional flags `--publish-dir ABSOLUTE_PATH`, `--web ABSOLUTE_PATH`, and `--listen HOST:PORT`. Their defaults are `/app/out`, `/app/web`, and `127.0.0.1:18080`. Unknown arguments, extra positional arguments, a missing database path, or a relative database/publication/web path are argument errors and exit 2. Registry-open or listener failures exit 3.

`GET /health` returns status 200 JSON `{"status":"ok"}`.

`GET /v1/campaigns/{campaign_id}/samples/{sample_index}/tile?revision={model_revision}` treats the campaign identifier as exactly one RFC 3986 path segment. Both sides must preserve that boundary. The certifier percent-encodes the identifier exactly once, using path-segment encoding rather than query encoding. For campaign `orbital/psf q3`, sample 4, and revision 23, the request target is exactly `/v1/campaigns/orbital%2Fpsf%20q3/samples/4/tile?revision=23`. The API routes by splitting the still-escaped path first, then percent-decodes only the campaign segment exactly once and compares the decoded value with the registry. It must not split a decoded path in which `%2F` has already become `/`. The sample index is a non-negative decimal integer. A malformed campaign segment, index, or revision is 400, an unknown sample is 404, and a revision mismatch is 409.

Success is the exact registered 8-bit grayscale PNG with `Content-Type: image/png`. The response `Cache-Control` field value must be exactly the case-sensitive string `no-store`; an absent value or any other value such as `max-age=3600` is a protocol failure that the certifier rejects before publication. Its strong ETag is exactly `"sha256:<digest>"`, including both quote characters and the literal `sha256:` prefix, where `<digest>` is the 64-character lowercase hexadecimal SHA-256 of the response body bytes. Success also includes exact `X-Campaign-ID`, `X-Sample-ID`, `X-Sample-Index`, `X-Site-ID`, `X-Device-Family`, `X-Label`, and `X-Model-Revision` headers.

The certifier percent-encodes the campaign as one path segment and requests each catalogue sample exactly once, in catalogue order, with `Accept: image/png`. It rejects redirects, unexpected statuses, duplicate or missing requests, bodies over 8 MiB, any `Cache-Control` value other than exact `no-store`, response metadata drift, any ETag not byte-equal to the required strong ETag, non-PNG content, PNGs whose decoded image is not 8-bit grayscale, and out-of-bounds ROIs. The release sample field `source_etag` preserves that exact quoted ETag string.

`GET /v1/releases/current?campaign={campaign_id}` resolves `/app/out/current.json`, verifies that it names the requested campaign and a release below the publication root, and returns the exact release bytes with `Content-Type: application/json; charset=utf-8`, `Cache-Control: no-store`, and the same exact ETag form `"sha256:<64 lowercase hex>"` computed from those bytes. Invalid campaign values are 400; a missing current release is 404; a broken or escaping publication reference is 500. `/dashboard`, `/assets/app.js`, and `/assets/styles.css` serve the release console.
