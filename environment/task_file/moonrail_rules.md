Moonrail match files are saved solo-board-game rounds. The player rides a lunar rail board, claims site emblems, and may stop after any round before heat ruins the journey. Site ids, link ids, emblem names, and contract ids are case-sensitive strings. Integers are decimal numbers. Empty arrays are valid everywhere an array appears.

Top-level fields are `version`, `start`, `round_limit`, `energy`, `energy_cap`, `heat`, `heat_limit`, `sites`, `links`, and `contracts`. `version` is a string. `round_limit`, `energy`, `energy_cap`, `heat`, and `heat_limit` are integers. `sites` is an array of objects with `id` string, `emblem` string, `points` integer, `rest` integer, optional `echo_points` integer, optional `late_penalty` object, optional `chain_points` object, optional `seal` array of emblem strings, and optional `block_rounds` array of 1-based round integers. A `late_penalty` object has `after` integer and `points` integer. A `chain_points` object has `after` site id string and `points` integer. `links` is an array of objects with `from`, `to`, and `id` strings, `cost` integer, `heat` integer, optional `requires` array of emblem strings, optional `consumes` array of emblem strings, optional `open_rounds` array of 1-based round integers, optional `quiet_max_heat` integer, optional `safe_revisit` boolean, and optional `bonus` object. A bonus object may contain `emblem` string, `energy` integer, or both. `contracts` is an array of objects with `id` string, `requires` array of emblem strings, `points` integer, optional `forbids` array of emblem strings, optional `final_heat_at_most` integer, optional `final_energy_at_least` integer, optional `route` array of site id strings, optional `claimed_order` array of site id strings, and optional `exclusive_with` array of contract id strings.

A plan starts at `start` before round 1. Each round selects exactly one directed link whose `from` is the current site. A plan may stop after any completed round, including round 0; it cannot exceed `round_limit`. A link is legal only when the current emblem multiset contains every entry in its `requires` array and every entry in its `consumes` array before taking that link. Repeated names in these arrays require that many copies. If `open_rounds` exists, the current 1-based round must be listed in it. If `quiet_max_heat` exists, the current heat before taking the link must be at most that value. The effective link cost is its `cost` plus the number of times that same link id has already been used in the current path. Effective cost is paid from current energy before arrival; if current energy is less than effective cost, that link is illegal. Effective link heat is its `heat`, plus 1 if the destination site already appears anywhere in the current path and `safe_revisit` is not true. Effective heat is added after the cost is paid; if heat becomes greater than `heat_limit`, that link is illegal. After the heat check passes and before arrival is evaluated, remove the entries named in `consumes` from the emblem multiset, then count that link id as used once more.

After a legal arrival, claim the destination site if it has not been claimed before, the destination id is not the start site, every emblem in its `seal` array is present after the link's `consumes` have been removed, and the current 1-based round is not listed in `block_rounds`. This seal check is made before the destination's own emblem, destination rest, or the link bonus is added; a bonus emblem from the same link can help later arrivals but cannot open the destination it just reached. These conditions are additive gates for that arrival: a blocked or sealed site still remains in the path, but it is not added to `claimed`, gives no points, gives no emblem, and does not trigger rest. Revisited sites remain in the path and are not claimed again. When a site is claimed, start with its points, subtract the `late_penalty.points` value if `late_penalty` exists and the current round is greater than `late_penalty.after`, then add `chain_points.points` if `chain_points` exists and the site named by `chain_points.after` was already in `claimed` before this claim. The claimed site score cannot go below 0 after the late penalty, but chain points are added after that floor. Then add its emblem to the multiset of claimed emblems, then add its `rest` value to energy without exceeding `energy_cap`.

After the site-claim step, apply the link bonus if present. A bonus with `energy` adds energy without exceeding `energy_cap`. A bonus with `emblem` adds that emblem to the claimed-emblem multiset but does not add a site to `claimed` and does not score site points. Final scoring also adds each claimed site's `echo_points` once if that site id appears at least twice in the final path; missing `echo_points` means 0. Contract completion is final-only: after the plan stops, first find the contracts whose required emblems are all present in the final multiset, counting repeated names; whose `forbids` emblems are absent from the final multiset; whose `final_heat_at_most`, if present, is at least the final heat; whose `final_energy_at_least`, if present, is at most the final energy; whose `route` array appears as a subsequence of the final path in the listed order; and whose `claimed_order` array appears as a subsequence of the final `claimed` array in the listed order. A missing or empty `route` or `claimed_order` array is already satisfied. These final contract gates are additive, not short-circuiting in the contract subset step: every eligible contract is considered before exclusivity is applied. Then choose the highest-point subset that has no exclusive pair. If either contract names the other in `exclusive_with`, the pair is exclusive and both cannot appear. If multiple contract subsets have the same point total, use the lexicographically smaller comma-joined sorted contract id list.

The selected result is the legal stopped plan with the highest total score, where score is claimed site points plus final echo points plus completed contract points. Ties compare the complete final result in this order: lower `final_heat`, then higher `final_energy`, then fewer entries in `path`, then lexicographically smaller path string using `>` between site ids, then lexicographically smaller comma-joined `contracts`. Output `claimed` in claim order and `contracts` sorted by contract id. If no legal move can be taken and stopping at round 0 completes no contract, output `score` as null, `path` as the one-item array containing `start`, empty `claimed` and `contracts`, and unchanged starting energy and heat.
