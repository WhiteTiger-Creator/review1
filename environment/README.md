# Certificate-Transparency Checkpoint Security Dossier

`/app/ctcheck` validates one certificate-transparency checkpoint dossier supplied as its only argument. The monitor uses this dossier to decide whether a TLS certificate log's signed tree head is authenticated, append-only, and safe to trust. It writes exactly one compact JSON object to stdout. Accepted dossiers produce `{ "status":"ACCEPT", "tree_size":N, "root_hash":"HEX" }`; rejected dossiers produce `{ "status":"REJECT", "reason":"CODE" }`. JSON may omit spaces, but field names, status strings, numeric tree size, lowercase hexadecimal roots, and one of the documented reason codes must be present. The process exits zero after either verdict and nonzero only for command-line misuse.

A dossier is UTF-8 text with one `key=value` pair per line. Empty lines and lines beginning with `#` are ignored. Keys are unique. Values for `log_id`, `public_key`, `old_root`, `old_sig`, `new_root`, `new_sig`, and each hash or leaf item are lowercase even-length hexadecimal. `old_size` and `new_size` are decimal non-negative integers. `entries` is a comma-separated list of leaf payloads in tree order, each as lowercase hex; it must contain exactly `new_size` items. `proof` is a comma-separated list of lowercase hex node hashes, or an empty value when no proof is needed. The cryptographic field lengths are exact: `log_id` is 9 bytes, `public_key` is 14 bytes, `old_root`, `old_sig`, `new_root`, `new_sig`, and every `proof` item are each 32 bytes. Leaf payloads in `entries` may be any byte length. A dossier is scoped to `/app/state/trusted.sth`, whose contents are exactly `log_id size root_hash` followed by a newline.

Checkpoint signatures use this deterministic offline transcript: `signature = SHA256(public_key_bytes || b"CTSTH\0" || log_id_bytes || b"\0" || decimal_tree_size_ascii || b"\0" || lowercase_root_hex_ascii || b"\0")`. The old checkpoint in the dossier must match the current trusted state and must have a valid signature. The new checkpoint must use the same `log_id`, must not decrease the tree size, and must have a valid signature.

Merkle tree hashing follows RFC6962 domain separation. A leaf hash is `SHA256(0x00 || payload_bytes)`. A parent hash is `SHA256(0x01 || left_child_hash || right_child_hash)`. The root of an empty tree is `SHA256(b"")`. For a non-empty tree, split the range at the largest power of two strictly smaller than the range length; hash the left and right ranges recursively and combine them with the node rule. `new_root` must equal the Merkle root of all supplied entries.

The consistency proof proves that the first `old_size` entries are an append-only prefix of the `new_size` entries. For this dossier format, the proof value is the ordered RFC6962 consistency proof for `(old_size, new_size)` over the supplied entries: recursively descend the same power-of-two range decomposition; if the old range lies entirely in the left half, emit the right subtree hash and continue left; otherwise emit the left subtree hash and continue right with the old range reduced by the left length. No proof entries are permitted when `old_size` is zero or `old_size == new_size`; otherwise the verifier must consume the proof in order and derive both the old root and new root from it.

Use reason `MALFORMED` for grammar, duplicate-key, integer, hex, cryptographic-field length, or missing-field failures; `STATE` when the trusted state cannot be read or does not match the dossier's old checkpoint; `SIGNATURE` for either invalid checkpoint signature; `ROOT` for a new root that does not match `entries`; and `CONSISTENCY` for a failed append-only proof or tree-size regression. The first applicable reason in that order wins. An accepted dossier must update `/app/state/trusted.sth` by writing a complete temporary file in `/app/state`, syncing it, renaming it over the old state only after all validation has succeeded, and syncing `/app/state` after the successful rename; the state directory may be opened before or after the rename. Rejected dossiers must leave the previous file byte-for-byte unchanged.
